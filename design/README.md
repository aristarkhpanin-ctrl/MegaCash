# Исходники дизайна

Макеты и техзадания лежат в репозитории, чтобы у кода был один источник правды
и его не приходилось искать по перепискам.

## Что здесь

| Файл | Что это |
|---|---|
| `tokens.json` | Токены: обе палитры, шкала шрифтов, отступы, радиусы, размеры. Идёт напрямую в `lib/core/theme` |
| `DesignSystem.dc.html` | Дизайн-система целиком: палитры, типографика, форма |
| `DSComponents.dc.html` | 14 компонентов во всех состояниях |
| `BankCard`, `CategoryTile`, `Chip` | Компоненты по отдельности, с логикой состояний |
| `ScreenA1`–`ScreenG2` | 17 экранов. Состояния заданы в блоке `data-props` внизу каждого файла |
| `Gallery.dc.html` | Индекс всех экранов |
| `zadanie-claude-code.md` | Техзадание на разработку |
| `zadanie-claude-design.md` | Техзадание на дизайн |

Файлы `.dc.html` открываются в браузере: `support.js` рендерит их и даёт панель
переключения состояний и темы.

## Где искать состояния экрана

Внизу каждого файла экрана — блок `data-props` с перечнем состояний. Это готовая
спецификация, по ней и делаются экраны. Например, у `ScreenB4` (проверка
распознанного) три состояния: `confident`, `uncertain`, `failed`.

## Известное расхождение

В `Gallery.dc.html` подписи группы Б устарели: там значатся «Выбор банка»,
«Способ ввода», «Импорт скриншотов». Сами файлы экранов Б2–Б8 соответствуют
техзаданию — скриншоты, распознавание, проверка, ручной ввод, рекомендация,
активация, готово. Источник правды — файлы экранов, не индекс.
