# МегаКэш

Android-приложение, которое подсказывает, какой картой платить, чтобы получить
больший кэшбэк.

Российские банки каждый месяц предлагают выбрать несколько категорий
повышенного кэшбэка из своего списка. У человека с пятью картами таких списков
пять, они пересекаются, и подобрать оптимальную комбинацию вручную практически
невозможно.

Приложение работает в два такта:

- **раз в месяц** — пользователь загружает скриншоты экранов выбора категорий из
  банковских приложений, приложение распознаёт их прямо на устройстве и выдаёт
  рекомендацию, что в каком банке выбрать;
- **каждый день** — пользователь нажимает нужную категорию и видит, какой картой
  платить.

Приложение с банками не интегрируется: категории пользователь активирует в
банковских приложениях сам. Данные живут только на устройстве, аккаунта нет.

## Стек

- Flutter 3.44 (Dart 3.12), цель — Android
- Riverpod 3 — состояние
- go_router — навигация
- Isar — локальная база (шаг 2)

Единственное сетевое обращение во всём приложении — загрузка справочника
категорий `categories.json`. Встроенная копия лежит в сборке, без интернета
приложение работает полностью.

## Структура

```
lib/
  core/          темы, токены, навигация, утилиты
  domain/        чистый Dart, без импортов Flutter
    models/      сущности
    optimizer/   алгоритм подбора категорий
    ocr/         интерфейс распознавания
    repositories/интерфейсы репозиториев
  data/
    local/       Isar, схемы, реализации репозиториев
    ocr/         реализация распознавания под Android
    remote/      загрузка categories.json
  features/      экраны по разделам
  ads/           рекламный модуль за интерфейсом
```

Слой `domain` не импортирует Flutter, Isar и платформенные пакеты — это условие
того, что оптимизатор покрывается обычными юнит-тестами без запуска приложения.

Три вещи спрятаны за абстракциями, потому что точно будут меняться:
`OcrEngine` (разные движки на Android и iOS), `AdsProvider` (рекламная сеть может
смениться), `CategoryDictionary` (сегодня файл в сборке, завтра загрузка
с сервера).

### Про распознавание

Движок за интерфейсом `OcrEngine`, всё после него — чистый Dart, поэтому
разбор проверяется на расшифровках настоящих скриншотов, без устройства.

**ML Kit не подошёл.** Он распознаёт латиницу, китайский, деванагари,
японский и корейский — кириллицы среди них нет. Для русского приложения
он бесполезен. Используется Tesseract с русской и английской моделями
в сборке: английская нужна для названий магазинов вроде Lamoda и WOLLMER.

Что показали настоящие скриншоты и чего не дала бы синтетика:

- **процент стоит перед названием** — «5% Супермаркеты». Разбор, рассчитанный
  на «Супермаркеты 5%», не нашёл бы вообще ничего;
- **половина списка — магазины, а не категории**: РИВ ГОШ, Lamoda, zolla,
  Кинопоиск. Их намеренно не сводят к категориям: «5% РИВ ГОШ» и «5% Красота» —
  разные предложения, и если склеить их, оптимизатор выбросит одно как дубль
  и отнимет у человека слот. Такие строки уходят пользователю;
- **условия отдельной строкой**: «Зарплатным клиентам», «С Альфа-Смарт»,
  «Только в приложении». Под ними предложение может быть недоступно, поэтому
  условие сохраняется вместе с предложением;
- **ВТБ пишет «Кешбэк» через «е»**, остальные через «э» — нормализация
  сводит оба написания к одному;
- **проценты бывают очень большими**: 80% на самокаты, 40% на подписку.

Пакет `packages/tesseract_ocr` взят в репозиторий и починен: опубликованная
версия объявляла собственный buildscript с AGP 8.2.1 и мёртвым jcenter,
из-за чего проект не конфигурировался под AGP 9.

### Про ответ у кассы

Повышенный процент действует только там, где категория выбрана. Если три банка
предлагают супермаркеты, а включены они в одном — в остальных двух вернётся
базовая ставка. Поэтому победитель на экране ответа определяется не по
предложениям банков, а по тому, что реально вернётся: у карты с выбранной
категорией — её процент, у всех остальных — базовый. Из этого же следует, что
карта с базовыми 5% обходит карту с выбранной категорией под 3%.

### Про оптимизатор

Ядро продукта — `domain/optimizer`. Задача о назначениях решается точно,
венгерским алгоритмом, а не жадным перебором: жадный не падает, он просто
тихо советует неоптимальное.

Главное правило: одну категорию нельзя выбрать в двух банках. Если три банка
дают супермаркеты под 7%, 5% и 3%, второй и третий слоты сгорают — в магазине
человек платит один раз и одной картой. В матрице назначений строка
используется не более одного раза, поэтому правило выполняется само.

Максимизируется не сумма ставок, а `вес × (ставка − наибольшая базовая)`:
без выбранной категории человек всё равно что-то получит, оптимизировать надо
прирост. Вес «На все покупки» равен сумме весов всех остальных категорий —
она совпадает с любой тратой, и иначе «2% на всё» всегда проигрывало бы
«7% на супермаркеты», хотя на деле выигрывает.

### Про базу данных

Техзадание называет Isar. Официальный пакет `isar` заброшен с апреля 2023 и
объявляет `sdk: <3.0.0` — с Dart 3.12 он не собирается вовсе. Используется
`isar_community` — поддерживаемый форк с тем же API.

Схемы хранилища (`data/local/entities.dart`) намеренно отделены от доменных
моделей: слой `domain` не должен знать про Isar. Между ними — преобразования
в обе стороны. После правки схем нужно перегенерировать код:

```bash
dart run build_runner build
```
